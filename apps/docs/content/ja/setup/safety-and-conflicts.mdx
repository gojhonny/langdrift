# 安全性と競合

セットアップは追加的で、非破壊的です。通常の実行が何かを書き込む前に、管理対象のすべてのファイルを計画します。

## プレビュー

```sh
langdrift setup \
  --root /path/to/product \
  --project-id proj_example \
  --account-id acc_example \
  --name 'Example Product' \
  --dry-run \
  --json
```

結果は、管理対象の各パスに 1 つのステータスを割り当てます。

- `create` — ファイルが存在せず、作成されることになります
- `preserve` — 解析した JSON が、すでに期待される値と等しいです
- `conflict` — 宛先を安全に再利用することも、作成することもできません

ドライランは検証を行い、書き込まずにこのプランを返します。ファイルが作成されることになる場合も含め、`changed` の値は `false` です。

## 保持と競合

JSON の比較は、空白とオブジェクトキーの順序を無視します。一致するファイルは、整形とタイムスタンプを含め、バイト単位で保持されます。既存のファイルが上書きされることはありません。

競合には、次が含まれます。

- 不正な、または切り詰められた JSON
- 解析した値が、要求されたプロジェクトまたは同梱スキーマと異なる通常ファイル
- 未対応のプロトコルバージョン
- 通常ファイルではない宛先
- ディレクトリではない、必須の親
- 管理対象パスのどこかにあるシンボリックリンク
- 既存プロジェクト上で変更された連携設定

プリフライトがいずれかの競合を見つけると、他の管理対象ファイルが欠けていても、セットアップは何も書き込みません。ファイルごとの理由を手動で確認してください。

レガシーの `.drifts/execution` パスは、常に競合です。バージョン 0.1.0 は `.drifts/loop` を使い、レガシーのレイアウトを移行、改名、マージ、削除しません。

## 書き込みと再実行

欠けているファイルは、排他的な作成で作られ、シンボリックリンクはたどられません。プリフライトのあとで宛先が現れた場合、解析した内容が一致すればセットアップはそれを保持します。一致しなければ、`SETUP_CONCURRENT_CHANGE` で失敗します。

変更のない再実行は `preserve` のみを報告し、`changed: false` を返します。欠けている必須スキーマは、その後の安全な実行で再作成されます。

書き込みの順序は、ファイルシステムのトランザクションではありません。1 つ以上のファイルが作成されたあとで、入出力または同時変更の失敗が起きた場合、それらのファイルは残ることがあります。既存の内容が上書きされることは、それでもありません。報告されたプランを確認し、無効なファイルがあれば見直し、セットアップを再実行して、残っている欠けたファイルを修復してください。
