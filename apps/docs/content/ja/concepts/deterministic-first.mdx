# 決定論を優先

LangDrift は、リポジトリそのものではなく、変化について推論します。リポジトリのファイルは構造化された入力です。正規化されたイベントと、その明示的な関係が、製品の動きを記述する単位です。

## 決定論的な処理

現在のパッケージは、再現可能な操作を実装しています。

- バージョン管理された JSON Schema に照らして、プロジェクト、アーティファクト、Record、Drift のデータを検証します。
- 明示的な `langdrift` フロントマターを解析し、Markdown の本文はテキストとして保持します。
- パッケージが宣言した `.drifts` の場所だけを、ソート順に、シンボリックリンクをたどらずに検出します。
- 不変のソース識別子が `recordId` に渡されたとき、安定した Record 識別子を導出します。
- リモート検索を行わず、明示的なローカル参照と登録済み参照を解決します。
- ルーティング、来歴、参照、検証済みの内容を持つペイロードエンベロープを構築します。
- セットアップを `create`、`preserve`、`conflict` として計画し、既存の内容の上書きを避けます。

検証は、値の強制変換、未知フィールドの削除、欠けている事実の補完、未対応バージョンの移行を行いません。セットアップはネットワークリクエストを行いません。

<Callout type="info">
**実装済み。** これらのスキーマ、解析、検証、検出、参照、ペイロード、セットアップの動作は、`0.1.0` リリース候補のソースで利用できます。
</Callout>

## 解釈の処理

アプリケーションまたは人が、なお決めることは次のとおりです。

- 観測された動きを、どの Vision Target と比較するか
- その動きが `expected` か `unexpected` か
- どの Evidence が解釈を支えるか
- どの影響の単位と値が適切か
- 推論が `human`、`deterministic`、`llm` のどれか
- Product Vision をどのように算出し、提示するか

SDK は、渡されたそれらの決定を記録し、検証します。SDK がそれらを正規の決定として定めることはありません。

## LLM 依存はありません

`@langdrift/sdk` は、LLM を同梱せず、呼び出しも、必須ともしません。Drift Event は、`human`、`deterministic`、`llm` の推論を宣言できます。`llm` が指定された場合、スキーマはモデル識別子と、リンクされた Evidence の ID を少なくとも 1 つ要求します。モデルを実行し、対応する出力を渡す責任は、引き続き呼び出し元にあります。

トランスポートも同じ境界に従います。アプリケーションは `sendPayload` にトランスポートを注入します。SDK は、稼働中のバックエンド、エンドポイント、キュー、自動再試行、自動アップロードを提供しません。
