# Environment variables must fail fast

## Decision

Configuration values that belong to environment variables must **not** have hardcoded runtime fallbacks in application code.

If a required environment variable is absent, the application must fail immediately with an explicit exception.

```ts
function requireEnv(name: string, value: string | undefined): string {
  if (!value) {
    throw new Error(`Missing required environment variable: ${name}`)
  }

  return value
}
```

Example:

```ts
export const env = {
  docsUrl: requireEnv('NEXT_PUBLIC_DOCS_URL', process.env.NEXT_PUBLIC_DOCS_URL),
  ssoUrl: requireEnv('NEXT_PUBLIC_SSO_URL', process.env.NEXT_PUBLIC_SSO_URL)
}
```

Do not implement:

```ts
const docsUrl =
  process.env.NEXT_PUBLIC_DOCS_URL || 'http://localhost:3004'
```

## Local development

Safe local defaults belong in tracked `.env.development`; secrets belong in ignored `.env`. Production values belong to the deployment platform. See [Environment file convention](./2026-09-20-environment-file-convention).

Example:

```env
NEXT_PUBLIC_SSO_URL=http://localhost:3002
NEXT_PUBLIC_DOCS_URL=http://localhost:3004
```

The Docs application currently uses port `3004` for local development. That value is therefore documented through environment configuration.

## Rationale

A missing required environment variable is a configuration error.

Silently falling back to a hardcoded value:

- hides developer mistakes;
- can point one environment at another unexpectedly;
- makes deployment behavior less explicit;
- duplicates configuration across code and environment files;
- allows an incorrectly configured build to appear healthy.

Fail-fast behavior makes the error visible at the point where the configuration is consumed.

## Rule

> Required environment variable missing → throw.

> Local/deployment value → env file or deployment environment.

> No hardcoded runtime fallback for environment-owned configuration.

## Current website application

For the website refinement, `NEXT_PUBLIC_DOCS_URL` and `NEXT_PUBLIC_SSO_URL` should both follow this rule.

Website and SSO links require explicit environment origins. Missing values no longer produce relative links. Docs requires `NEXT_PUBLIC_SITE_URL`; the Website Server Function requires server-only `EMAIL_SERVICE_URL` and `EMAIL_SERVICE_API_KEY`.
