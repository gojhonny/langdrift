# 確定性優先

LangDrift 針對變更進行推理，而不是針對儲存庫。儲存庫檔案是結構化輸入；正規化事件及其明確關係，才是用來描述產品移動的單位。

## 確定性工作

目前的套件實作可重現的操作：

- 對照帶版本的 JSON Schema 驗證專案、產物、Record 與 Drift 資料；
- 解析明確的 `langdrift` 前置資料，同時把 Markdown 本文保留為文字；
- 只發現套件宣告的 `.drifts` 位置，依排序順序進行，且不跟隨符號連結；
- 當不可變的來源身分提供給 `recordId` 時，衍生穩定的 Record 身分；
- 解析明確的本機與已登錄參照，不進行遠端查詢；
- 組裝帶有路由、來源出處、參照與已驗證內容的承載資料封套；
- 把設定計畫為 `create`、`preserve` 或 `conflict`，並避免覆寫既有內容。

驗證不會強制轉換值、移除未知欄位、填補缺少的事實，或遷移不支援的版本。設定不會發出網路請求。

<Callout type="info">
**已實作。** 這些結構描述、解析、驗證、發現、參照、承載資料與設定行為，可在 `0.1.0` 發行候選版本的原始碼中使用。
</Callout>

## 解讀工作

應用程式或人仍然決定：

- 觀察到的移動應與哪個 Vision 目標比較；
- 該移動是 `expected` 或 `unexpected`；
- 哪項 Evidence 支持這項解讀；
- 哪個影響單位與哪些數值適當；
- 推理是 `human`、`deterministic` 或 `llm`；
- Product Vision 如何計算與呈現。

SDK 記錄並驗證這些由外部提供的決策。它不會把它們訂為標準。

## 不依賴大型語言模型

`@langdrift/sdk` 不內建、不呼叫、也不要求大型語言模型。Drift Event 可以宣告 `human`、`deterministic` 或 `llm` 推理。當提供 `llm` 時，結構描述要求模型識別碼與至少一個連結的證據 ID；執行模型並提供受支援的輸出，仍由呼叫端負責。

傳輸遵循相同界線。應用程式把傳輸注入 `sendPayload`；SDK 不提供運作中的後端、端點、佇列、自動重試或自動上傳。
