# 安全與衝突

設定只做附加，且不具破壞性。在一般執行寫入任何內容之前，它會先規劃每一個受管理檔案。

## 預覽

```sh
langdrift setup \
  --root /path/to/product \
  --project-id proj_example \
  --account-id acc_example \
  --name 'Example Product' \
  --dry-run \
  --json
```

結果會為每個受管理路徑指定一個狀態：

- `create` — 檔案缺少，且將會被建立
- `preserve` — 解析後的 JSON 已經等於預期值
- `conflict` — 目的地無法被安全地重複使用或建立

預演會驗證並回傳此計畫，不會寫入。其 `changed` 值為 `false`，包含將會建立檔案的情況。

## 保留與衝突

JSON 比較會忽略空白與物件鍵順序。相符的檔案會逐位元組保留，包括其格式與時間戳。既有檔案絕不會被覆寫。

衝突包括：

- 格式錯誤或被截斷的 JSON
- 一般檔案的解析值與要求的專案或隨附結構描述不同
- 不支援的協定版本
- 目的地不是一般檔案
- 必要的父層不是目錄
- 受管理路徑的任一處是符號連結
- 既有專案的整合設定已變更

若預檢發現任何衝突，設定不會寫入任何內容，即使其他受管理檔案缺少也一樣。請手動檢視各檔案的原因。

舊版 `.drifts/execution` 路徑一律構成衝突。版本 0.1.0 使用 `.drifts/loop`，不會遷移、重新命名、合併或移除舊版配置。

## 寫入與再次執行

缺少的檔案以獨占方式建立，且不跟隨符號連結。若目的地在預檢之後才出現，且解析內容相符，設定會保留它。否則會以 `SETUP_CONCURRENT_CHANGE` 失敗。

沒有變更的再次執行只會回報 `preserve`，並回傳 `changed: false`。缺少的必要結構描述會在之後一次安全執行中重新建立。

寫入順序不是檔案系統交易。若在建立一個或多個檔案之後發生 I/O 或並行變更失敗，那些檔案可能仍然留在原地。既有內容仍然不會被覆寫。請檢查所回報的計畫、檢視任何無效檔案，並再次執行設定，以修復仍然缺少的檔案。
